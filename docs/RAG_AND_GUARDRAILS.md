# Retrieval, generation and guardrails

## Current hosted Research integration (owner approved 2026-11-09)

D9/D10 now use Laws.Africa Uganda Knowledge Bases, replacing the local ingestion, embedding,
vector/full-text fusion, reranker and parent-expansion requirements in sections 1–3 for this path.
The provider owns indexing/ranking; no local corpus text or vector model is introduced.
Research calls legislation-ug and judgments-ug concurrently, filters returned metadata to Uganda,
excludes future versions and non-current legislation, and interleaves collection results without
comparing incompatible scores. Last three user questions (capped at 4000 characters) inform follow-ups;
this is bounded context, not a separate semantic rewrite/classifier.

Owner confirmed whole-answer withholding on 2026-11-09: any failed paragraph blocks all answer text.
This supersedes partial-segment removal/threshold behavior in section 5 for hosted Research.
Groq returns schema-validated answer segments with retrieved source IDs and exact evidence excerpts. No answer text streams until
all IDs, evidence-to-source mappings, literal evidence/quotations and a separate model support/authority check pass. Any rejection, missing
sources, malformed output, timeout or upstream failure withholds the answer and refunds before a delta.
The original generic availability error is reused; an owner-supplied dedicated abstention message,
urgent/refusal routing and full advocate safety/accuracy evaluation remain open. No replacement legal
wording is authored. Drafting template flows are unchanged; generic Drafting chat remains without retrieval.

Citation metadata (IDs, title, URL, source date, collection) is persisted under the message owner and
shown as links with dates in the existing answer paragraph. Retrieved passages are transient server memory,
not committed or cached. Static generation/verification prompts are versioned files. The verifier is a
separate call using the same configured provider/model, not an independently calibrated legal judge.
See [integration record](LAWS_AFRICA.md) and STATUS.md for verification and limitations.

The sections below retain the broader target behavior, except the local pipeline superseded above.

## 1. Ingestion
- Source manifests list each source, licence and permitted use. Ingest only manifest-approved sources.
- Parse by legal structure: Act, Part, Section, subsection for legislation. Facts, issues, holding, reasoning for judgments. Never split on fixed length alone.
- Chunk size 300 to 800 tokens. Every chunk stores a parent section id.
- Before embedding, prepend one line of context (document, part, heading), generated by a small model and stored.
- Each chunk records citation, valid_from, valid_to and in_force. Repealed or superseded provisions stay stored but are excluded from search by default.
- OCR output below a quality threshold is quarantined for manual repair, never indexed.
- Ingestion is idempotent by content hash and runs only in workers, admin-triggered.
- Re-embedding to a new model runs side by side and swaps without downtime. embed_model is stored on every row.
- A process for ingesting new Acts, amendments and gazette notices must exist before launch. A stale corpus is a defect.

## 2. Embeddings
- Choose by benchmark (D10): at least 200 advocate-written queries with correct sections. Compare recall at 20 and MRR. Report results in evals/.
- Queries and documents use the model's required prefixes.
- Store reduced-precision vectors. Index with HNSW. Tune search breadth against the recall target. Confirm filtered-search behaviour on the chosen pgvector version (Milestone 0).

## 3. Query pipeline (in this order)
1. Classify the request: legal question, drafting, out of scope, urgent, chit-chat.
2. Rewrite follow-ups into a standalone question using conversation context.
3. Resolve explicit citations (for example, a named section of a named Act) by exact lookup first.
4. Run vector search (top 50) and full-text search (top 50), both restricted to in-force provisions and Uganda.
5. Merge using reciprocal rank fusion.
6. Rerank the top 30 with a cross-encoder reranker, keep 6 to 10.
7. Expand each hit to its parent section, plus definitions and cross-referenced provisions.
8. Order by authority: Constitution, Acts, statutory instruments, higher court, lower court. Pass conflicts to the model labelled as conflicts.
9. If the best reranker score is below the tuned threshold, skip generation and return the abstention response.

## 4. Generation
- The system prompt, tool list and mode prompt live in versioned files. Changing them triggers the full eval suite.
- Output is structured: answer segments, each with the chunk ids that support it, plus an optional clarifying question.
- Retrieved text is data, never instructions. It is wrapped and labelled as untrusted.
- Temperature low. Output length capped. Prompt caching enabled for the static prefix.

## 5. Citation verification (blocking)
Before any answer is shown as final:
1. Every cited chunk id must be in the retrieved set. Otherwise the segment is removed.
2. Any case name, Act name or section number in the text that does not appear in the retrieved text is removed or the answer regenerates once.
3. Quoted text must be a literal substring of the cited chunk.
4. Each claim is checked against its cited chunk by a separate verification step. Unsupported claims are removed.
5. If more than a set fraction of the answer is removed, return the abstention response.
6. Every citation shows source link and the law-as-at date.
Verification catches invented citations. It does not catch a wrong reading of a real provision. See RISKS.md R4.

## 6. Guardrails
Input:
- Jurisdiction: Uganda only. Other countries get a plain scope message.
- Urgent situations (arrest, detention, violence, self-harm, minors in danger) bypass retrieval and return verified emergency and legal aid contacts supplied by the owner, then offer to continue.
- Prompt injection: scan user text and uploaded content for instruction patterns. Treat results as signals, not proof. Tools have no more permissions than the user.
- Language: per D11.
Policy:
- Never claim to be a lawyer. Never guarantee outcomes. Never state a deadline as certain; state the rule and tell the user to confirm with an advocate.
- Mandatory advocate referral topics: criminal charges, imminent court dates, custody, land disputes, amounts above a configurable limit.
- Refuse requests to forge, backdate or evade. Log as blocked.
Output:
- Disclaimer shown on every legal answer (owner-supplied text).
- Drafting: unknown facts stay as bracketed placeholders, never invented. Dates and amounts are checked for internal consistency.
- Template values are escaped. No user text is ever interpreted as markup or formulas in generated files.

## 7. Prefill
- Output validated against the template's field schema. Unknown fields rejected. Values the user did not state are null.
- Confidence below threshold returns template candidates and asks the user to choose.

## 8. Observability
Trace every request: query, rewritten query, retrieved chunk ids, scores, reranker scores, abstain decision, verification removals, tokens, cost, latency. Message text in traces is redacted unless explicit consent is on file.

Hosted prompt revision v2 requests one concise, independently supported paragraph rather than
multiple speculative paragraphs. Every cited source requires a nonblank exact excerpt; excerpt
matching does not replace the separate semantic support check. Verifier input includes explicit
zero-based indexes. The whole-answer gate and quota refunds remain unchanged.
